# “粘贴为文件”设计

## 目标

让用户主动决定是否把文本或图片历史保存为文件，避免普通粘贴因为资源管理器焦点识别不准确而误保存。

## 交互

- 普通点击记录：保持现有行为，粘贴到打开历史面板前的目标输入位置。
- 文本和图片记录在卡片右侧操作区显示“粘贴为文件”按钮。
- 文件记录不显示该按钮。
- 点击按钮后只保存到资源管理器当前文件夹；非资源管理器目标不执行保存并提示用户切换目标窗口。

## 实现

- `MainWindow` 保存按钮所在记录和面板打开前的目标窗口句柄，复用现有卡片操作事件。
- `ExplorerFilePaste` 提供显式保存入口，负责资源管理器窗口识别、当前文件夹解析、文件命名和写入。
- 普通 `ClipboardPlayback.PlayAsync` 不主动触发文件保存；“粘贴为文件”按钮单独调用保存入口。
- 保存成功后刷新资源管理器目录，失败时在状态栏给出原因，不修改剪切板内容。

## 文件规则

- 文本保存为带 UTF-8 BOM 的 `.txt`。
- 图片统一转为 `.png`。
- 文件名使用 `PasteOrbit_yyyyMMdd_HHmmss`，冲突时追加数字后缀。

## 验证

- 普通点击文本/图片能粘贴到记忆中的输入框。
- 资源管理器文件夹视图点击“粘贴为文件”能生成对应文件。
- 非资源管理器窗口点击按钮不会生成文件。
- 无效目标窗口、权限错误和无当前文件夹时均不崩溃并给出状态提示。
